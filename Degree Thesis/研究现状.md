## 1 引言

6G 无线网络正从"以通信为中心"向"通信 + 算力 + 智能"融合演进。沉浸式 XR、具身智能、动态感知等新业务对端到端时延、可靠性与算力提出严苛要求，单一节点难以独立完成大模型推理，端边云协同成为必然选择 [^4SACTEP7] [^MGXNAN7Z] [^XLBFXS3G] [^ZLFY6VPF]。

然而，将 LLM 类大模型部署到端边云异构环境面临三方面挑战：

1. **业务多样性**：多业务并发请求差异显著（实时性、精度、连续性），需要灵活的任务建模与编排机制；
2. **节点异构性**：端-边-云节点在算力、显存、链路带宽、能耗上量级差异巨大，需要动态节点选择策略；
3. **上下文长程依赖**：长上下文业务的 KV 缓存随 token 累积产生巨大状态传输代价，需要跨节点加速机制。

围绕上述挑战，学界已从 LLM 推理引擎 [^PZ4JRSWC] [^BYH4SDXK] [^SVBEVTB8]、多智能体任务编排 [^7P8HPCH8] [^V4WT27HK] [^NYJUQSBN]、边云协同部署 [^Z9ZUL5Q6] [^Y2XQPJB7] [^XN2MZJMM] [^PZ4JRSWC] [^ECSEZU27]、O-RAN 资源调度 [^SZ2YMTG4] [^LJQGR7LI]、长上下文压缩 [^UGVRS8CA] [^RZCFHBSX] [^W9EMGP53] [^CP96NIIZ] 等角度展开研究。本章从任务建模与编排、节点选择、长上下文加速三方面综述研究现状，并分析现有工作不足。

## 2 任务建模与动态编排研究现状

### 2.1 多业务请求的任务分解

任务分解是协同推理的入口，其目标是将复杂业务请求拆解为可调度的子任务 DAG，并明确依赖关系。现有工作沿三条路径展开：

**对话式分解**。AutoGen [^7P8HPCH8] 提出基于 LLM 对话的 agent 协作框架，通过定义 agent 角色与消息协议，让 LLM 在多轮对话中自动协商出子任务及其依赖。该范式灵活但缺乏显式结构化描述。TDAG [^V4WT27HK] 进一步将任务依赖建模为有向无环图（DAG），提供可执行的工作流描述。

**自动工作流合成**。AFlow [^NYJUQSBN] 把工作流合成问题形式化为搜索问题，通过蒙特卡洛树搜索自动发现高质量的 agent 协作拓扑。AOP [^F44HPP87] 提出编排 agent（Orchestration Agent）模式，由专门的 agent 负责规划、调度与监控其他 agent。

**运行时自验证与自适应**。Advancing Agentic Systems [^MNXG7M6S] 强调任务分解应随上下文动态调整。AutoMix [^YN8AR7WI] 在不同复杂度模型间自动切换，并以自验证机制保证输出质量。SpecInfer [^YU9MYS4F]、Sarathi-Serve [^34WPR8NY]、Splitwise [^JMCNDGXD]、DistServe [^TEFURCC5] 则在推理引擎层面提供 prefill-decode 解耦与 chunked pipeline 编排。

### 2.2 模型路由与请求级调度

当任务粒度细化为"单次推理请求"时，路由决策（用哪个模型、放在哪个节点）成为关键。RouteLLM [^TLGE4QG6] 用偏好数据训练路由器，在强模型与弱模型之间分配请求以平衡成本与质量。Hybrid LLM [^H8EUZIHQ] 引入云-端混合范式，简单请求本地处理、复杂请求云端推理。FrugalGPT [^6D24T5FG] 提出级联调用策略，按置信度逐级升级模型。

### 2.3 推理引擎层面的服务编排

vLLM [^PZ4JRSWC] 提出 PagedAttention，通过分页管理 KV cache 显存，将显存碎片降至接近零，奠定高吞吐 LLM 服务基础。SGLang [^BYH4SDXK] 引入 RadixAttention，利用前缀树复用跨请求的 KV，显著降低重复计算。Mooncake [^SVBEVTB8] 提出 KVCache-centric disaggregated 架构，将 prefill 与 decode 节点解耦并以 KV 为中心调度。

### 2.4 现有不足

任务分解研究普遍假设**任务依赖是事先已知或由 LLM 推断**，缺少与无线链路/节点负载**显式耦合**的任务建模；模型路由决策以请求为单位，**未与节点能力画像和链路状态联动**；推理引擎层面的编排目前主要在云数据中心内优化，**未延伸到端-边-云广域异构环境**。

## 3 端边云协同推理节点选择研究现状

### 3.1 经典 DNN 时代的算力-带宽联合优化

早在 LLM 普及之前，端云协同推理已是通信学科研究热点。Neurosurgeon [^URU27SA3] 首次系统化提出"在算力-带宽权衡曲线上最优划分 DNN 各层"，将端云协同建模为延迟最小化问题。DNN Surgery [^KFJR4HIB]、Edge AI [^V3WPXS7B]、JLN5G4EQ [^JLN5G4EQ]、SPINN [^R2YA433J]、M4T3NZI4 [^M4T3NZI4] 在此基础上考虑异构性、能量收集、管道并行等扩展场景。Task-Oriented Communication for Edge Inference [^I7Y7MR37] 从信息瓶颈角度出发，把"为推理任务的通信"作为优化对象。

这些工作建立了端云协同推理的经典理论框架，是当前 LLM 时代研究的对照基线。

### 3.2 LLM 时代的边云协同

**边缘协同**。EdgeShard [^Z9ZUL5Q6] 提出基于计算图的协同推理，在端-边-云多个 DPU 间划分 LLM 各层。LLMCad [^Y2XQPJB7] 设计端侧 LLM 推理加速器，利用模型嵌套与早退降低时延。Petals [^XN2MZJMM] 采用去中心化 BitTorrent 风格的多方协作推理，将 LLM 各层分配到志愿者节点。Mobile Edge Intelligence for LLMs [^MGXNAN7Z] 与 Edge Intelligence [^XLBFXS3G] 综述了边云 LLM 协同的整体研究图景。

**VLA 与多模态协同**。OpenVLA [^HN7P2PZH]、DeeR-VLA [^MVUC8V6G] 将动态推理思想扩展到视觉-语言-动作模型，在机器人场景中根据任务复杂度早退或切换模型。

### 3.3 跨节点 KV Cache 传输与调度

LLM 推理的核心状态是 KV cache。异构节点之间高效迁移 KV 是 2024-2025 年研究热点。

- **HexGen / HexGen-2** [^U5Q6G7LU] [^J6LTZJPX]：提出异构 disaggregated 生成式推理架构，给出带宽-算力拓扑感知的调度策略。
- **TopKV** [^WU5HIEXI]：设计 Top-K 重要 KV 块的选择与跨节点迁移算法，避免整块搬运。
- **KVDirect** [^QDYI3BG8]：在异构节点间建立 KV 直传通道，降低传输延迟。
- **SmartGen** [^UZMWM3CX]：异构 KV 调度框架，根据节点能力画像分配 KV 块。
- **BanaServe** [^JNESFVG6]：明确引入带宽感知调度，将网络状态作为决策变量。
- **Nexus** [^HLFWCSU4]：统一调度器，整合边云节点资源池。
- **Mooncake tradeoffs** [^ECSEZU27]：分析 KVCache 中心化架构在真实部署中的通信代价权衡。

### 3.4 O-RAN 与无线侧的调度

通信学科另一条主线是 O-RAN 无线资源调度。Actor-Critic Network for O-RAN xApp [^SZ2YMTG4] 用 actor-critic 强化学习在 xApp 层面做 RB 分配。ML-based xApp for O-RAN [^LJQGR7LI] 进一步用机器学习决策 QoS 保障策略。

### 3.5 现有不足

- **决策粒度脱节**：DNN 时代工作在层/模块粒度优化，LLM 时代工作在请求/任务粒度优化，二者尚未形成跨粒度联合调度框架；
- **链路动态性未充分建模**：HexGen-2 等工作虽然考虑拓扑，但**未把无线链路的小尺度衰落、切换、抖动显式建模**；
- **KV 传输效率**：跨节点 KV 迁移的研究集中在"哪些 KV 要搬"，**对"如何高效传输"（压缩、差分、编码）的关注不足**；
- **O-RAN 与 LLM 编排割裂**：xApp 调度与 LLM 推理调度是**两套独立决策体系**，可能产生冲突（如 xApp 把 RB 分给某业务但 LLM 把该业务推理放到远端云），目前**没有联合建模工作**。

## 4 长上下文跨节点推理加速研究现状

### 4.1 投机解码（Speculative Decoding）

投机解码是 2023-2025 年最强的 token 级加速方向之一。Leviathan et al. [^JRD55MAS] 与 Chen et al. [^QQZM4NDC] 几乎同期提出草稿-验证范式。EAGLE [^EMA5QERA] 与 EAGLE-2 [^5TGJPEFJ] 进一步引入特征层不确定性建模与动态草稿树。Medusa [^B6EANCHQ] 用多头并行预测降低单步延迟。LayerSkip [^CWRPDDJD] 将早退与自投机结合。

### 4.2 早退与动态深度

BranchyNet [^KSGM4VDC] 首次在 DNN 中引入早退分支。CALM [^Q3A2PZUT] 把早退思想扩展到 LLM，根据置信度决定是否提前停止生成。Mixture-of-Depths [^GFWA378X] 在训练阶段就允许不同 token 跳过不同层。

### 4.3 KV Cache 压缩与稀疏化

**重要性评估**。H2O [^W9EMGP53] 发现 KV 注意力分数呈重尾分布，提出保留 heavy-hitter。SnapKV [^RZCFHBSX] 用累积注意力分数评估 token 重要性。Quest [^3K2LKUWX] 进一步实现查询感知的 KV 稀疏化。Model Tells You What to Discard [^BGMQS4RR] 自适应选择丢弃位置。

**量化**。KIVI [^UGVRS8CA] 证明 KV 可在 2bit 量化下保持精度，提出非对称量化方案。StreamingLLM [^CP96NIIZ] 提出 attention sink 机制，使模型能在固定窗口下处理超长流。

### 4.4 多模态 token 稀疏化

多模态场景下的视觉 token 稀疏化是新兴方向。FastV [^6EE3P5JY] 发现在视觉-语言模型前几层之后，大半视觉 token 可被丢弃。Token Merging [^R2JAHFU7] 通过 token 合并降低 ViT 计算量。

### 4.5 现有不足

- **压缩与传输脱节**：现有 KV 压缩方案以**单节点显存**为优化对象，**对跨节点传输中的压缩/差分编码关注不足**；
- **多模态长上下文研究空白**：现有加速方法主要针对纯文本 LLM，**面向 XR/具身智能等多模态长上下文业务的加速方案较少**；
- **节点切换的连续性**：跨节点切换时**上下文和中间状态迁移机制尚未充分研究**，新节点往往从零开始，造成"切换损失"。

## 5 现状评述与研究空白

综合 §2–§4 的综述，可以总结当前研究的三个主要空白：

### 5.1 任务-节点联合决策缺位

现有工作**在三个层面各自优化**：
- 任务编排层假设节点能力静态已知；
- 节点选择层假设任务依赖固定；
- 上下文加速层假设推理节点不变。

三者没有形成闭环的联合优化框架，导致系统级次优。需要**任务分解-节点选择-KV 复用**三者联合决策的协同机制。

### 5.2 无线链路状态与推理调度的耦合松散

通信侧 O-RAN xApp 调度与 LLM 推理节点选择是**两套独立决策体系**，二者各自优化局部指标，可能产生冲突。**当前没有"xApp 资源分配 × 推理节点选择"联合建模工作**。在 6G 算力网络背景下，这一缺口尤其突出。

### 5.3 跨节点 KV 传输效率待提升

长上下文业务的 KV 在跨节点迁移时**整块搬运**，带宽代价大。KIVI/SnapKV 等压缩方案以单节点为对象，**未与跨节点传输协议联合设计**。基于率失真理论的差分压缩-传输联合设计是潜在方向。

### 5.4 业务画像与节点画像的联动不足

现有路由/混合方案（RouteLLM, Hybrid LLM, FrugalGPT）以**请求-模型**匹配为决策粒度，**未考虑业务上下文连续性和节点能力画像**。在多业务并发、节点异构的端边云环境下，需要**业务画像 × 节点画像**的精细匹配机制。

## 6 本章小结

本章围绕"多业务分布式协同推理"主题，从任务建模与编排、端边云节点选择、长上下文加速三个层面综述了 59 篇相关文献的研究现状。研究表明：

1. **任务建模**已从单一模型路由演进到 multi-agent 工作流合成与运行时自适应，但与无线环境的耦合仍较松散；
2. **节点选择**从 DNN 时代的算力-带宽联合优化演进到 LLM 时代的跨节点 KV 调度，2024-2025 年论文密度显著增加，但无线链路动态性仍未充分建模；
3. **长上下文加速**已形成 speculative decoding、early-exit、KV 压缩三大技术路线，但与跨节点传输的结合尚不充分。

三个层面共同面临的核心问题是**缺乏联合优化框架**：现有工作各自优化局部指标，未将任务分解、节点选择、KV 复用纳入统一决策。在 6G 算力网络与多业务并发场景下，**任务-节点-上下文三层耦合的协同推理** 是值得深入研究的方向，这正是本论文的研究动机。

下一章将基于上述分析，提出**业务感知 + 无线链路耦合的多业务任务编排与节点选择算法**。
