# DT-JEPA 实验方案：JEPA 作为辅助自监督分支（路径 C）

**基础论文**：Zhang et al., "Decision Transformers for Wireless Communications: A New Paradigm of Resource Management" (IEEE Wireless Communications, 2025)
**目标**：在不改变原 DT 架构主干和训练流程的前提下，并联一个 JEPA 自监督分支，验证其能否用更少的专家样本达到同等或更优的资源管理性能，并提升对新场景的泛化能力。

---

## 1. 研究问题与假设

### 1.1 原始 DT 的局限
- DT 完全依赖 PPO/启发式算法生成的**专家动作标签**做监督学习，本质是行为克隆（behavior cloning）的序列化版本。
- 一旦专家样本稀缺或包含次优/失败轨迹，DT 无法从中提取有效信息，只能被动模仿。
- DT 学到的表征完全由"预测动作"这一个任务驱动，没有显式约束模型去理解环境的**动态演化规律**（比如 CSI 如何随时间变化、UAV 移动会如何改变负载分布）。

### 1.2 核心假设
> 在共享的 Transformer 编码器上，额外引入一个"预测未来状态隐表征"的自监督目标（JEPA），可以强迫模型学到更贴近环境动态本质的表征，从而：
> 1. 减少对专家标签数量的依赖（可利用非专家/失败样本）；
> 2. 提升在新场景（不同 IRS 元件数、不同 UAV 数量）下少样本微调的收敛速度和最终性能。

---

## 2. 总体架构设计

```
                         ┌─────────────────────┐
   历史序列 (s_t, a_t, R̂_t, prompt)  →  │  共享 Transformer 编码器 E_θ │
                         └──────────┬───────────┘
                                    │  h_t (隐表征)
                    ┌───────────────┴───────────────┐
                    ▼                                ▼
          ┌───────────────────┐           ┌─────────────────────┐
          │  动作预测头 (原DT) │           │  JEPA 预测器 P_φ      │
          │  â_t = f(h_t)     │           │  ẑ_{t+k} = P_φ(h_t)  │
          └─────────┬─────────┘           └──────────┬──────────┘
                    │                                  │
              L_DT (MSE/CE)                    L_JEPA (L1, stop-grad)
                    │                                  │
                    ▼                                  ▼
             与专家动作 a*_t 比较              与 EMA 目标编码器
                                                E_θ̄(s_{t+k}) 比较
```

### 2.1 模块说明

| 模块 | 说明 |
|---|---|
| **共享编码器 E_θ** | 复用原论文的 3 层因果 Transformer block（自注意力+前馈+残差+Dropout 0.1），输入仍是时间嵌入后的 (state, action, RTG, prompt) 序列 |
| **动作预测头** | 原论文结构不变，输出预测动作 â_t，用 MSE（连续动作，如 BS 功率）或 CE（离散动作，如 IRS 相移档位）计算损失 |
| **JEPA 预测器 P_φ** | 新增小型 MLP 或轻量 Transformer，输入为 t 时刻隐表征 h_t，输出对 t+k 时刻状态隐表征的预测 ẑ_{t+k} |
| **EMA 目标编码器 E_θ̄** | 与 E_θ 结构相同，参数通过 EMA 更新：θ̄ ← m·θ̄ + (1-m)·θ（建议 m=0.996，参考 V-JEPA 系列常用值），只做前向，不接收梯度（stop-gradient） |

### 2.2 为什么用 EMA + stop-gradient
延续你之前讨论过的机制：如果目标编码器直接用 E_θ 且不停梯度，预测损失会驱使编码器把所有输入都塌缩成同一个常数向量（表征坍塌），因为"预测一个恒定值"是损失为零的捷径解。EMA 让目标缓慢演化、stop-gradient 切断了这条捷径，是防止坍塌的关键设计，必须在实现里严格保留。

## 3. 损失函数

**总损失：**

```
L_total = L_DT + λ · L_JEPA
```

- **L_DT**（原始动作预测损失）：
  - 连续动作（如 BS 发射功率）：`L_DT_cont = MSE(â_t, a*_t)`
  - 离散动作（如 IRS 相移档位）：`L_DT_disc = CrossEntropy(â_t, a*_t)`
  - 混合动作空间：沿用原论文的**动作嵌入技术**（离散动作最近邻匹配 + 连续动作自回归生成），分别计算后加权求和

- **L_JEPA**（隐预测损失，L1）：
```
L_JEPA = (1/K) · Σ_{k=1}^{K} || P_φ(h_t) − sg[E_θ̄(s_{t+k})] ||_1
```
  其中 `sg[·]` 表示 stop-gradient，K 为预测步数（建议先从 K=1 开始，再扩展到 K=3~5 做多步预测消融）

- **λ（权重系数）**：建议在 {0.1, 0.5, 1.0, 2.0} 中做网格搜索，作为核心消融变量之一

## 4. 数据与场景设计

沿用原论文的两个场景，但需要补充设计非专家/混合质量样本，以体现 JEPA 的样本效率优势：

### 4.1 IRS 辅助通信场景
| 项目 | 设置 |
|---|---|
| 系统组成 | 1 BS + 1 IRS + 1 MU（预训练场景），迁移到 128 / 64 元件的新场景做少样本微调 |
| 状态 | CSI + 上一时刻数据速率反馈 |
| 动作 | BS 发射功率（连续）+ IRS 相移（离散量化档位） |
| 奖励 | 即时数据速率 / QoS |
| **专家样本** | PPO 收敛后策略生成的轨迹 |
| **新增：非专家样本** | PPO 训练过程中早期（未收敛）阶段的轨迹，或加入随机探索噪声的轨迹 —— 用于测试 JEPA 分支能否从"低质量"数据中提取环境动态信息 |

### 4.2 UAV 辅助 MEC 场景
| 项目 | 设置 |
|---|---|
| 区域 | 100×100 m²，10 个用户，Gaussian Markov 移动模型 |
| 状态 | UAV 位置 + 剩余电量 + 任务队列 |
| 动作 | 路径规划 + 用户关联 + 卸载决策 |
| 奖励 | 吞吐量 / 时延 / 能效 |
| 新场景 | 3 架 → 4 架 UAV（或更极端：3 → 10 架做零样本/极少样本泛化测试） |
| 非专家样本 | 同上，PPO 早期轨迹 + 随机策略轨迹 |

### 4.3 仿真平台建议
由于原论文未开源、未指定平台，建议：
- 用 **Python + PyTorch** 自建环境，遵循 **Gymnasium（原 OpenAI Gym）接口**（`reset()` / `step()` / `observation_space` / `action_space`），方便同时对接 PPO（用 Stable-Baselines3 或自实现）和 DT/JEPA 模型
- IRS 信道模型：需要找到原论文引用的参考文献 [5]（Zhang et al., 2022, IEEE JSTSP，多智能体 RL 的 IRS 网络）里的具体信道建模公式作为基础（如需要我可以帮你检索并解读这篇文献）
- UAV 移动性：Gaussian Markov mobility model 有现成的开源实现可参考（如 `pymobility` 库）

## 5. 训练与评估流程

### 阶段一：云端预训练
1. 用 M 个历史场景的专家+非专家混合样本训练：`L_total = L_DT + λ·L_JEPA`
2. Baseline 对照组：纯 DT（λ=0，无 JEPA 分支）用相同数据训练

### 阶段二：边缘少样本微调
1. 在新场景（128/64 IRS 元件；3/4 架 UAV）中，仅用极少量样本微调
2. 对比三组：
   - **纯 DT**（原论文方法）
   - **DT + JEPA（本方案）**
   - **PPO from scratch**（原论文的另一 baseline）

### 阶段三：消融实验矩阵

| 消融维度 | 取值 | 目的 |
|---|---|---|
| λ（JEPA损失权重） | 0（无JEPA）, 0.1, 0.5, 1.0, 2.0 | 验证JEPA分支的贡献是否随权重单调，找到最优点 |
| K（预测步数） | 1, 3, 5 | 验证单步 vs 多步隐预测对长时序任务（UAV路径规划）是否有额外收益 |
| 专家样本比例 | 100%, 50%, 20%, 10% | 核心实验：验证样本效率提升，画出"性能-样本量"曲线 |
| EMA动量 m | 0.99, 0.996, 0.999 | 验证目标编码器更新速度对稳定性的影响 |
| 是否用非专家样本训练JEPA分支 | 是/否 | 验证JEPA能否真正利用低质量数据（这是DT本身做不到的） |

## 6. 评估指标

1. **任务性能指标**（与原论文对齐，便于直接对比）
   - IRS 场景：平均数据速率（b/s/Hz）
   - UAV 场景：每回合累计吞吐量（Mb）
2. **收敛速度**：达到 baseline 收敛值 95% 所需的 epoch 数
3. **样本效率**：达到固定性能阈值所需的专家样本数量（核心新增指标，用于体现 JEPA 的价值）
4. **泛化能力**：零样本或 1-shot 迁移到全新场景（如 5 架 UAV、更多元件数的 IRS）时的初始性能
5. **表征质量诊断**（可选，用于论文里做深入分析）
   - 隐空间坍塌检测：计算 batch 内隐向量的方差/有效秩（effective rank），确认 JEPA 分支未坍塌
   - t-SNE/UMAP 可视化不同场景下的隐表征分布

## 7. 预期产出与后续扩展

- 若路径 C 验证有效（即 JEPA 分支能显著提升样本效率或泛化性），可作为核心实验支撑一篇会议/期刊论文的主体贡献
- 若效果有限，诊断可能原因（λ 过小、K 设置不当、非专家样本质量太差），并考虑升级到**路径 A**（JEPA 独立预训练表征器）以获得更强的表征能力
- 长期可扩展方向：把 UAV/IRS 场景统一到同一个 JEPA 预训练编码器上，验证跨任务（IRS ↔ UAV）表征迁移的可能性——这将是你笔记中"三阶段架构"里"世界模型"层的直接实验支撑
