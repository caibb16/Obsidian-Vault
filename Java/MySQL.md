## 索引
索引的定义就是帮助存储引擎快速获取数据的一种数据结构，形象的说就是**索引是数据的目录**
### 数据存储
InnoDB 的数据是按「数据页」为单位来读写的，数据页大小默认为16KB，也就是说数据库每次至少从磁盘读取16KB的内容到内存中，数据页之间通过双向链表连接，数据页中的记录按照「主键」顺序组成单向链表。

只有叶子节点存放数据，非叶子节点仅存放目录项作为索引。主键存储是有序的，定位记录时，通过二分法快速定位到包含该记录的页，之后在该页内进行二分法快速定位记录到所在的分组，最后在分组内进行遍历查找。
### 聚簇索引和二级索引
- 聚簇索引：叶子结点存放实际数据（数据行），只能有一个
- 二级索引：叶子结点存放主键值
如果某个查询语句使用了二级索引，但是查询的数据不是主键值，这时在二级索引找到主键值后，需要去聚簇索引中获得数据行，这个过程就叫作「回表」，也就是说要查两个 B+ 树才能查到数据。不过，当查询的数据是主键值时，因为只在二级索引就能查询到，不用再去聚簇索引查，这个过程就叫作「索引覆盖」，也就是只需要查一个 B+ 树就能找到数据。
### 联合索引
多个字段组合成一个索引，且字段存在先后顺序，使用联合索引时存在**最左匹配原则**。
例如联合索引(a, b, c)，是先按 a 排序，在 a 相同的情况再按 b 排序，在 b 相同的情况再按 c 排序。所以，**b 和 c 是全局无序，局部相对有序的**。
### 查询性能影响
树是存储在磁盘中的，树的高度等于每次查询数据时磁盘 IO 操作的次数，所以树的高度越高，就会影响查询性能。
- 二叉查找树 -> 极端情况退化为链表，时间复杂度从O(logn)降为O(n)
- 平衡二叉查找树 -> 作为二叉树，由于每个节点只能保存 2 个子节点，插入元素增多时树高度不可避免的增加，降低查询效率
- B树 -> 一个节点允许有M个子节点(M>2)，从而降低树的高度
- B+树 -> B树的升级，只有叶子节点存放实际数据，所有索引都会在叶子节点出现，叶子节点之间构成一个有序链表
## 事务
事务特性：原子性，一致性，隔离性，持久性
### 事务隔离级别
- 读未提交：可以读到未提交的事务
- 读提交：每次读取数据时都会生成一个新的Read View
- 可重复读：启动事务时生成一个Read View，然后整个事务期间都在用这个 Read View
- 串行化：所有事务串行执行
