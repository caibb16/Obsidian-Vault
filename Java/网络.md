### 键入网址到网页显示
1. 浏览器解析URL并生成HTTP消息
2. 客户端向本地DNS（通常由网络运营商自动分配）请求目标服务器的IP地址，当然如果本地有缓存可以直接查到
3. 拿到 IP 地址后，浏览器与服务器之间通过 **三次握手** 建立 TCP 连接。三次握手目的是**双方都保证双方都有发送和接收的能力**，一条 TCP 连接建立后，可以在上面连续发送多个 HTTP 请求。
4. 传输过程：路由器逐跳转发，知道下一站的 IP 地址之后（这一IP不会记录），接下来需要通过**ARP**协议根据 IP 地址查询 MAC 地址，并将查询的结果作为接收方 MAC 地址（ARP协议只在同一局域网内发送广播请求）。转发过程中目标IP地址作为最终目的地始终不变，每次转发MAC 头部都会被丢弃重装，（MAC 头部的作用就是将包送达路由器，其中的接收方 MAC 地址就是路由器端口的 MAC 地址）

## 应用层
- http协议：HTTP 是一个在计算机世界里专门在「两点」之间「传输」文字、图片、音频、视频等「超文本」数据的「约定和规范」，具体来说包括请求数据和响应数据的格式规范。
### GET和POST
- GET：从服务器获取指定资源
- POST：根据请求负荷对指定资源做出处理
### 缓存技术
将请求-响应的数据缓存在本地，重复请求直接读取本地数据
- 强制缓存：第一次访问时，HTTP响应头会加上有效期字段，之后访问只要浏览器判断缓存没有过期，则使用本地缓存，主动权在浏览器
- 协商缓存：本地资源过期时，浏览器与客户端协商，服务器收到请求后进行比对，如果资源没有变化响应HTTP 304走缓存，如果资源变化了则返回最新资源
### HTTPS（HTTP+SSL/TLS）
#### TLS协议建立流程（四次握手）
1. 客户端向服务器发起加密通信请求 Client Hello
2. 服务器收到客户端请求后，向客户端发出响应 Sever Hello，以及 Server Certificate 消息，该消息包含数字证书
3. 客户端收到服务器的回应之后，首先通过浏览器或者操作系统中的 CA 公钥，确认服务器的数字证书的真实性。如果证书没有问题，客户端会**从数字证书中取出服务器的公钥**，然后使用它加密报文，协商后续通信
4. 双方通过协商的加密算法，计算出本次通信的**会话秘钥**（对称加密），验证加密和解密没问题
至此，整个 TLS 的握手阶段全部结束。接下来，客户端与服务器进入加密通信，就完全是使用普通的HTTP 协议，只不过用「会话秘钥」加密内容。
#### 非对称加密算法
公钥和私钥一起生成，在数学上紧密相连。用公钥加密的数据，只能用配套的私钥解密；反之，用私钥加密的数据，也只能用配套的公钥解密。
- 公钥加密，私钥解密：目的是保证内容传输的安全
- 私钥加密，公钥解密：目的是保证消息不被冒充
非对称加密的主要用途是通过「私钥加密，公钥解密」的方式来确认消息的身份。为了解决漏洞“你怎么确定你拿到的公钥，真的属于你想通信的那个人，而不是黑客冒充的？”，引入解决方案：数字证书与权威机构（CA）
